# セキュリティアドバイザリ対応のための ONTAP バージョンアップ手順 / ONTAP Upgrade Procedure for Security Advisories

## この文書の位置づけ / Scope of this document

セルフマネージドの ONTAP（オンプレミスの NetApp ONTAP、ONTAP Select、Cloud Volumes ONTAP）を、NetApp のセキュリティアドバイザリへの対応としてバージョンアップするときの計画に使う手順を、3 製品 × 5 段階（アドバイザリの確認、事前確認、実行、事後確認、リバート）で並べる。

- 手順の各項目は、NetApp の公開ドキュメントの記述を整理したもので、実環境で実行した結果ではない。tier は `documented`（出典の URL を開いて該当の記述を読んだ）と `open`（読めていない。手順に入れず「未確認事項」に置く）の 2 種類で、`verified` の項目はない
- 確認日はすべて 2026-11-13（日本時間）。出典の URL を開き、該当の記述と、出典が対象とする ONTAP の版が載っていることを見た日である。「出典の対象版」の列は、出典のページが対象と書く版で、手順がその版で動くことを確かめたものではない
- 手順項目の数は、日本語の節と英語の節で一致させている（段階 1 から 5 の表の行の合計 42）
- コマンドと REST のパスは、出典に書かれた形を写した。実行する前に、自分の ONTAP の版の文書で引数を確かめる

This document lays out, in 5 stages for each of 3 products, the procedure for planning a version upgrade of self-managed ONTAP (on-premises NetApp ONTAP, ONTAP Select, Cloud Volumes ONTAP) as a response to a NetApp security advisory. The stages are: confirming affected and fixed versions, pre-checks, running the upgrade, post-checks, and revert.

- Each procedure item is an organised reading of NetApp's public documentation. It is not the result of running the procedure in a real environment. The tier is `documented` (the source URL was opened and the passage was read) or `open` (not read; kept out of the procedure and listed under open items). No item is `verified`
- Every confirmation date is 2026-11-13 (Japan time): the day the source URL was opened and the passage, together with the ONTAP version the source covers, was seen on the page. The "Version covered by the source" column is the version the page itself addresses. It does not mean the procedure was shown to work on that version
- The number of procedure items is the same in the Japanese and English sections (the sum of the table rows in stages 1 to 5)
- Commands and REST paths are copied in the form the sources give. Check the arguments against the documentation for your own ONTAP version before running them

## 範囲外と送り先 / Out of scope and where it goes

Amazon FSx for NetApp ONTAP（以降 FSx for ONTAP）と、他のクラウド事業者の ONTAP ベースのサービスのバージョンアップは、この文書で扱わない。これらのサービスの更新は、この文書の出典（セルフマネージドの ONTAP の文書）を読んだ範囲に含まれていない。実環境での確認は、第 2 の柱（責任の分担と SLO）の spec に送る。この文書の手順を、それらのサービスにそのまま当てはめない。

アドバイザリの配信を機械で読む照合は、この文書の外にある。`scripts/netapp_advisory_match.py` が RSS 2.0 を読み、非公開の台帳の各行に「該当あり」「該当なし」「判定保留」の案を作る。案は人が 7 日以内に確定する。この文書が扱うのは、確定した後に、バージョンアップを計画して実行する段である。

Version upgrades of Amazon FSx for NetApp ONTAP (FSx for ONTAP hereafter) and of ONTAP-based services from other cloud providers are not covered here. The sources read for this document are about self-managed ONTAP and do not cover those services. Confirmation in a real environment is sent to the spec for the second pillar (division of responsibility and SLOs). Do not apply this procedure to those services as it stands.

The machine-read matching of advisories sits outside this document. `scripts/netapp_advisory_match.py` reads the RSS 2.0 feed and proposes "affected", "not affected" or "verdict on hold" for each row of a private ledger. A person confirms each proposal within 7 days. This document covers what comes after the confirmation: planning and running the version upgrade.

## 段階 5: リバート / Stage 5: Revert

リバートは復旧点を減らす操作だと読める（解釈）。出典は、Snapshot のポリシーを止めること、更新後に作った Snapshot を消すこと、Tamperproof Snapshot を使うボリュームではロックが満了するまでリバートできないこと [E-057] を書いている。サイバーレジリエンスの設定（Snapshot のロック、ARP の Snapshot）を使っている環境では、「更新して問題が出たら戻す」を計画の前提に置く前に、次の表を読む。

## 経路の選び方 / How to choose a path

どの経路も、出典が書く前提を満たしていれば使える。次は出典の記述からの解釈で、特定の経路を推すものではない。

| 経路 | 向く場合（解釈） | 考慮点 |
|---|---|---|
| ONTAP CLI | System Manager の自動更新に対応しない構成。手順をコマンドで記録したい場合 | 事前チェックと進捗の確認を自分で順に実行する。MetroCluster の 4 ノード以上ではノードごとに進捗を見る |
| ONTAP REST API | 更新を自動化の仕組みに組み込む場合。`validate_only` で検証だけを先に行える | スキーマと、パッケージを REST で取得する方法を読めていない（O-5） |
| System Manager | オンプレミスで NetApp の推奨に従う場合（ANDU） | 構成によっては対応しない。単一ノードは停止を伴う |
| NetApp Console | Console を既に管理面に使っていて、サポート契約がある場合。Cloud Volumes ONTAP は Console が NetApp の文書にある経路 | 契約が前提。Console agent を置くとクラウドの課金が生じる。全工程を Console で行うのは 9.12.1 以降 |

Any path can be used when the prerequisites in the sources are met. What follows is interpretation of the sources, and does not favour a particular path.

| Path | Suited to (interpretation) | Considerations |
|---|---|---|
| ONTAP CLI | Configurations outside what System Manager's automated upgrade handles; teams that want the procedure recorded as commands | You run the pre-checks and progress checks yourself, in order. On MetroCluster with 4 or more nodes, progress is viewed node by node |
| ONTAP REST API | Embedding the upgrade in an automation framework; running validation alone first with `validate_only` | The schemas and the way to fetch the package over REST were not read (O-5) |
| System Manager | On-premises, following NetApp's recommendation (ANDU) | Some configurations are outside its automated upgrade. A single node is disruptive |
| NetApp Console | Environments that already use the Console for management and hold a support contract. For Cloud Volumes ONTAP it is the path in NetApp's documentation | A contract is required. Placing a Console agent incurs cloud charges. All steps run in the Console only from 9.12.1 |
